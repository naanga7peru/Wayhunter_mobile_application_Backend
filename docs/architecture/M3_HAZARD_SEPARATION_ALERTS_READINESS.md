# M3 hazard and separation alert readiness

SOURCE: Active Rules and M3-MS01-T02 specify route-scoped hazards within 1 km, photo capture time and a 24-hour warning window from server report time. ADM-08/09/16 are the M3 Admin responsibilities listed in M3_SCOPE. Existing Admin moderation and report status remain separate from a participant's live warning state.

The code-only evaluator reuses the existing hazard matching query and the same live-location access reader used by the authenticated SignalR hub. It scopes warnings to trip, session, participant and hazard. A matched hazard moves from detected to active when the first warning is returned. Repeats are suppressed until the configured cooldown, and acknowledgement stops repeats. Resolution requires acknowledgement. Retrying either current terminal action returns the current state. The existing hazard query excludes moderated and expired reports from warning results. A local resolution has no effect on the community report.

Separation evaluates two server-stamped samples in the same trip and active session, with access checked for both users. Proposed boundaries are separation at or above the configured distance and recovery at or below the lower recovery distance. Maximum sample age is inclusive. Stale, future and invalid samples do not change the episode. Per-pair timestamp ordering and a shared lock suppress replay and simultaneous duplicate transitions. The evaluator retains identifiers, timestamps and alert state in bounded process memory, with no stored GPS coordinates or trails.

## DECISION_REQUIRED before activation

- M2 and M3 must approve a trip-specific authoritative planned-route geometry contract, including route revision and invalidation. The live evaluator requires the M3-owned IAuthoritativeTripHazardRouteReader seam, which has no production adapter. The existing hazard query still uses its separate unavailable stop-based provider. Route preview and historical segments are not authoritative for this integration.
- Product owners must approve cooldown, separation and recovery thresholds, maximum sample age/accuracy, warning recipient policy, acknowledgement/resolution semantics and any client-facing HTTP or SignalR contract.
- DB Coordinator must approve retention, durable keys and concurrent writes for multi-instance operation. Staging state resets on restart. Expired hazard state is pruned, and pair state has a process-local capacity with no eviction. Session teardown, consent-generation fencing, pair cleanup, and transactional membership/consent checks must be settled before activation. A membership or consent change after the last read can race an evaluation.
- The evaluator is available as a backend service, with inert settings and no public endpoint, SignalR call, timer, FCM or notification worker. Binding approved settings, supplying fresh paired samples and delivering results are deferred activation work. Existing M3 endpoints, Start/Finish, Safe Check-in, MS07 and MS08 wiring are untouched.
