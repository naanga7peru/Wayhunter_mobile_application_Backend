## Submit and evidence relational boundary

Current tables now support the internal Draft-to-PendingReview write with timestamp, trusted name snapshot and revocation in one transaction. Durable idempotency still needs a unique owner/submission/operation-key record with payload fingerprint and committed response reference; an already PendingReview row does not prove an identical replay. Current evidence rows have a private media reference but lack authoritative upload identity, capture binding and a globally unique canonical media key. Approve provider namespace and canonical identity normalization, unique constraints for upload and canonical media replay, and capture-to-evidence linkage. Keep atomic evidence insertion/consumption disabled until those rules can be enforced together.

REWARD-01 verification covers the existing source query and outbox exclusion using EF InMemory. End-to-end reconciliation and ledger idempotency require an isolated shared-model setup with the tables actually queried by the M6 source and outbox processor.
